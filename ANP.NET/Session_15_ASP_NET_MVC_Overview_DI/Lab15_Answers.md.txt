### G.1 You deleted OnConfiguring in Part C.3 and the class stopped being able to connect to
    anything on its own. Explain why making the class less capable made the application more flexible.

Deleting "OnConfiguring()" made the "StudentPortalContext" depend on Dependency Injection instead of configuring itself. 
This made the application more flexible because the connection is now provided by "Program.cs" allowing different projects to use the same context with different databases 
or configurations without modifying the context class.


### G.2 In Part D.2 the app failed because of a type nobody registered. That failure happened without
    a single line of your controller code running. Why is failing at startup better than failingon the first user request?

The application failed because "StudentPortalContext" was not registered in the Dependency Injection container 
so ASP.NET Core couldn't create the "HomeController". Detecting this problem before any controller code runs is better.
